### 5. Learnings

- **A remote branch my clone has not fetched is indistinguishable from a branch
  that does not exist.** `git branch -a` here listed only `master` and
  `origin/master`, and I was one keystroke from filing "the `reports` branch
  does not exist, so `emailDailyReport` will fail every weekday" as a blocker.
  `git ls-remote --heads origin` returned `refs/heads/reports = baf828c`. The
  branch is fine; my clone was stale. **Behavioural change:** every claim about
  a *remote* ref cites `git ls-remote`, never `git branch -a`. Proposed as a
  line in the `daily-report` skill's shared-facts gather — section 7.
- **Documentation drift is most likely in the commit that writes both halves.**
  `a296c01` changed `server.js` and the one `cto` skill line describing it, and
  they disagree (item 3 above). The same-commit case is the one that feels
  safest and gets checked least. **Behavioural change:** when a change touches a
  skill and the code that skill describes, I diff the two halves against each
  other before it is cleared, and I treat a literal (a cron expression, a port,
  a schedule) in a skill the same way that skill treats line numbers — as
  something that rots silently. Report #1's own citation shifted from
  `server.js:1063` to `server.js:1064` in one commit, which is the same lesson
  in miniature.
- **Capability scan (`T2`/`E2`): not run this window.** Recorded as an absence,
  not dressed up as a quiet result. Due 2026-09-19 per section 1.
- **Report #1's proposal was not adopted, and nobody was going to notice.** It
  asked for `du -sh` on untracked directories in the skill's step 2;
  `grep -n "du -sh" .claude/skills/daily-report/SKILL.md` → no match. A proposal
  filed in section 7 with no one assigned to it is a note, not a change.
